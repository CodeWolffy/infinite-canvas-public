# Go 公益创作平台

本分支面向受邀用户提供图片、视频、文本和音频创作。用户选择平台模型即可生成，管理员集中配置上游渠道、价格、签到与充值。生产入口是 `server/` Go 服务；`api/` 保留为公司版接口参考，不参与 Docker 运行。

## 运行结构

- React / Vite / Ant Design：创作工作台、无限画布、用户中心和管理后台。
- Go / Gin / pgx：会话鉴权、渠道调用、任务调度、账务与支付通知。
- PostgreSQL：账号、邀请码、任务、消息、画布、素材、订单及不可变余额明细。
- Redis：跨实例账号/IP 频控与渠道并发槽位；开启 AOF，不承担余额记账。
- MinIO：图片、视频和音频对象，通过经过登录鉴权的 `/api/media/:id` 读取，支持 Range。

任务和预冻结记录在同一数据库事务内创建。工作进程使用 `FOR UPDATE SKIP LOCKED` 领取任务，通过唯一执行标识防止迟到回调覆盖已取消或已重试的任务。文件或文本结果持久化成功后才结算；失败或取消退回冻结余额。

渠道按优先级分层、同层按权重选择，同一渠道的并发槽位由 Redis 跨实例共享。每个任务默认最多尝试 3 次（含首次），限流、超时、鉴权和可重试上游故障会切换候选渠道；鉴权失败只停用对应 Key，还可使用该渠道其他 Key。没有剩余候选或次数耗尽时退回原冻结金额，自动切换不会重新冻结或重复向用户收费。内容政策拒绝、无效参数不重试；已有文本输出、取得异步任务 ID 或上游已成功返回结果后，不再重复提交生成。

尝试次数、失败渠道、使用过的 Key、上游受理编号与加密渠道快照写入 PostgreSQL；重启后继续使用同一尝试预算。过期执行先接管原租约，再按已知错误和剩余次数决定切换或退款；已受理视频仅凭原快照续查，手动更换渠道密钥不影响该任务。上游在返回任务 ID 前超时，受理结果可能不明，各次上游成本分别保留；平台用户仍只结算最终一次结果。每个实例默认启动 20 个工作协程，实际跨实例上游并发受渠道配置约束。

## 余额与支付

数据库以整数微元记录金额，1 元 = 1,000,000 微元；充值金额精确到分。图片按张计价；文本可按次或按输入、缓存命中、输出 token 计价；视频可按请求秒数计价，音频可按 ffprobe 读取的产物时长计价。缓存单价留空表示采用输入单价，0 表示免费。创建、重试和报价统一使用分组折扣与价格快照。

模型售价与预报价保留有效小数位，例如 `0.008` 显示为 `0.008`，不补多余的零。用户模型菜单展示对应的按张、按次、按秒或输入/缓存/输出 token 单价，继续采用当前分组折扣。

工作台展示服务端计算的预冻结额。文本按上下文与管理员配置的最大输出 token 预估；音频沿用 5 秒预估，管理员可设置最低预冻结金额。完成后只写一次结算差额，多余冻结退回；补扣不足时沿用冻结额封顶，计算费用与用户实付分别记录。预冻结不是最终账单，失败或取消释放冻结余额。

模型的「渠道配置」可独立填写人民币上游成本。成本账保留每次调用的价格快照，来源区分「未知」「配置估算」「人工核对」，清理请求日志不会清理成本账；已成功调用上游但结果保存失败时仍保留相关成本。管理端「成本与公益补贴」分别显示用户账本实付、已知成本、已知成本超过实付的部分和已发公益额度；未知成本不按零费用处理，估算不能代替渠道账单。人工核对必须填写依据并记录审计。

每日签到按 `Asia/Shanghai` 自然日计算，使用安全随机数在管理员指定的区间内发放。默认关闭签到，管理员填写区间后开启。签到、充值与手动调整都写入余额明细；并发签到只领取一次，同一充值订单只入账一次。

用户余额、签到、邀请奖励和兑换码到账金额永久保留，不按日、周或月清零，不设置周期赠送和周期消费额度。管理员额外赠送使用兑换码；同一用户可兑换不同码，同一码只能兑换一次。钱包中的本月汇总仅用于统计，不影响可用余额。分组保留价格折扣、模型权限与存储配额：默认不限模型，空的允许列表表示不能生成；存储配额 0 表示关闭，超限拒绝上传或结果保存并退回失败任务的冻结金额。历史领取记录及余额账本保留，周期领取接口已移除。

## 渠道、审核与邀请扩展

此前渠道扩展已通过本机 Docker 构建、启动和自动回归；本轮充值返利、价格与文本交互调整仍需验收，见 [待测试清单](content/docs/progress/pending-test.mdx)。迁移 `012_channel_routing.sql`、`013_moderation_and_rewards.sql` 由 Go 启动流程执行：已有渠道密钥转入独立加密 Key 表，移除周期规则字段，保留钱包、签到和历史账本。Go 与 Web 需同步更新。

- **多 Key**：渠道编辑中每行添加一个 Key，默认轮询，可选择随机；只回显掩码与状态。鉴权失败仅停用该 Key，管理员可单独启用或删除。已受理任务使用加密快照续查。
- **自动停用**：连续 3 次有效检测失败后停止新任务调度。内容政策拒绝、无效参数和本地存储问题不累计为渠道健康故障。冷却后按原检测间隔检查，一次成功恢复；自动检测间隔仍默认 0，仅手动检测时也需要手动触发恢复检查。
- **耗时统计**：任务、生成探针和在线调试均保存完成耗时；渠道 p50/p95 使用成本账中所有已保存且成功的耗时样本，不以失败请求充当慢响应样本。
- **模型状态**：`/status` 与 `GET /api/status/models` 均需登录，状态页使用工作台布局。接口只返回已发布模型的汇总状态与检查时间。依据具体绑定的生成探针聚合；只有模型列表检测时不会显示生成正常。未检测、或自动检测超过已配置间隔未更新时显示待检测；不公开渠道地址、密钥、检测提示词与错误详情。
- **内容审核**：`block` 直接拒绝，`review` 生成待审核记录，`log` 只记录。文本、图片、视频、音频的提示词和文本参数都检查。管理员在敏感词页面通过或拒绝，审核决定与排队/退款同事务完成；用户可取消等待。再次手动重试会重新检测，不绕过审核。被拒绝的文本不会进入后续对话上下文。
- **邀请返利**：推荐链接与注册邀请码独立，注册只建立邀请关系。默认关闭，管理员配置 `referralPercent` 百分比后按好友每笔实际支付的充值金额返利，比例取到账时配置；不足一个微元的部分舍去。支付入账、邀请返利、累计记录与通知在同一事务完成，以支付订单去重。签到、兑换码和注册不返利，重新开启不补发已入账订单，余额永久保留。
- **文本输出上限**：管理员在模型配置 `config.maxOutputTokens` 中填写正整数，无默认值。用户文本对话、工作台和画布不展示该输入项；后端覆盖客户端的 `max_tokens`、`max_completion_tokens`、`maxOutputTokens`，统一用于报价和任务快照，未配置时在冻结前拒绝。已受理任务与幂等重放保留原快照。
- **思考强度**：管理员在模型配置 `config.reasoningEfforts` 中选择实际支持的 `low`、`medium`、`high`、`xhigh`、`max`、`ultra`，公开模型接口下发对应选项，文本对话、工作台和画布共用。留空表示仅用模型默认；「自动」不发送显式强度。后台在报价与创建任务时校验档位，规范化 `reasoningEffort` / `reasoning_effort` 并拒绝冲突，不允许用户绕过模型配置。OpenAI 兼容接口使用 `reasoning_effort`；[Claude 使用 `output_config.effort`](https://platform.claude.com/docs/en/build-with-claude/effort)；[Gemini 使用 `generationConfig.thinkingConfig.thinkingLevel`](https://ai.google.dev/api/generate-content#ThinkingConfig)，原生接口需选择支持该字段的模型和档位，当前仅支持其中的 `low/medium/high`。各渠道并不通用全部档位。
- **Claude**：用户生成采用上述模型输出上限，缓存读取用量按缓存价格处理，缓存写入用量计入当前输入价格；达到输出上限按正常完成结算。管理员的渠道检测和调试台继续使用独立的检测参数。
- **任务适配器**：`GET /api/admin/task-adapters` 列出已接入的 `openai-video` 和 `gemini-video`，实现位于 `server/internal/platform/task_adapters.go`；统一提交/续查接口，复用任务快照、账务与存储。即梦、可灵、Vidu、原生 Sora 和 Suno 尚无实际渠道接口文档，目前保留待接入入口；不代表已支持这些第三方 API，音乐能力尚未开放。

## 账号、通知与主动检测

在「运营设置 → 邮件与通知」填写 SMTP 主机、端口、TLS/STARTTLS、发件地址和认证信息。密码加密保存。邮箱验证与找回链接有效期为 30 分钟且只能使用一次；找回接口对存在和不存在的邮箱返回相同提示。未绑定验证邮箱的账号仍由管理员重置密码，密码找回不会关闭已有两步验证。

用户可在「账号安全」绑定验证器；启用后登录先验证密码，再验证 TOTP，登录凭证 5 分钟有效。启用时提供一个仅显示一次的恢复码；恢复码登录会关闭两步验证并撤销其他设备，请随后重新绑定。设置、验证和找回沿用现有登录保护。设备列表可查看 IP、浏览器和有效期，支持撤销单个或其他会话。密码修改、邮箱验证、两步验证变更、管理员重置密码，以及 IP 与浏览器组合未见过的新登录会写入通知中心；充值、兑换、公益额度和签到到账同样通知，可用余额低于 1 元时每天最多提醒一次。

「渠道管理 → 主动检测」按具体绑定选择一个或多个上游模型（配置字段为 `bindingIds`），设置检测提示词与参数、模型列表检查，以及 dashboard/billing 渠道的美元余额提醒阈值。自动间隔默认 0，表示只手动执行；设置正整数分钟后启用。列表页按图片、文本、视频、音频分类，仅提交当前类型内已配置的启用渠道。检测与生成共享 Redis 渠道槽位，遵循当前超时与冷却；繁忙时排队。生成检测会产生真实上游费用，写入成本账，结果不进入用户素材库。模型变化先提示管理员核对，不自动发布或删除模型。模型已绑定渠道但当前全部不可用时，每小时最多通知管理员一次。

在线调试台支持文本和图片，沿用同一渠道槽位及检测成本处理。排队跟随请求取消，执行超时使用渠道配置；可取消请求，离开页面也会停止等待，不自动重发。响应包含图片预览、实际 HTTP 状态、首字耗时和脱敏后的原始 JSON/SSE 事件。测试不扣用户余额；只有唯一匹配的绑定才采用其成本配置，其余记录为未知成本。检测成本保留原截止时间，进程中断后由恢复任务结束，不重放上游请求。

渠道「测试」与「配置模型」共用模型列表探测接口，失败时显示脱敏的网络错误或上游 HTTP 状态。若同一渠道在服务器可用、本机失败，并提示域名解析到 `198.18.x.x` 等保留地址，检查本机 Mihomo / Clash 的 Fake-IP DNS：将实际渠道域名加入代理的 `fake-ip-filter` 排除列表，刷新代理配置后确认容器解析到真实公网 IP。平台继续拦截内网和保留地址。

故障、恢复、模型变化与余额不足产生站内通知，管理员验证邮箱且邮件服务启用后同时接收邮件。相同状态不反复通知；邮件投递失败保留站内记录和投递状态，不自动无限重试。检测进程中断或超时会记为失败，未知成本保留为未知，不重放原生成请求。

## 文本流式输出

OpenAI 兼容文本使用流式 Chat Completions，Gemini 使用流式 generateContent，Claude 使用原生 Anthropic Messages（渠道协议 `anthropic`）。首段立即持久化，后续沿用任务轮询节奏合并写入，完成后持久化正式消息并结算。工作台与画布接收 SSE，断线可读取服务端片段和最终快照；最终消息按请求与消息 ID 去重。关闭本地等待只关闭订阅，主动取消由任务取消接口执行；切换登录会话会关闭旧订阅并丢弃旧回复。

Web Nginx 已关闭 `/api` 响应缓冲。生产环境的 1Panel 外层反代也应关闭 SSE 缓冲，避免浏览器只能在结束后看到整段文本。本地 Agent 继续独立运行。

## 支付渠道

支持以下支付接口，渠道与订单快照中的敏感配置均加密保存：

- 易支付经典 MD5 接口：支付宝、微信支付。配置 HTTPS 网关、商户 ID 和商户密钥。主动查单依赖 `api.php?act=order`。经典协议无统一远端关单接口，确认未支付后只关闭本站入口，迟到的有效支付仍会入账；查单结果不明时保留待确认订单。
- 支付宝官方当面付：配置 App ID、收款支付宝用户 ID、应用私钥和支付宝公钥，调用官方收单接口预下单、查单与关单。
- 微信支付官方 Native API v3：配置 App ID、商户号、商户证书序列号、商户私钥、API v3 密钥、微信支付公钥 ID 与公钥。

支付回调地址由 `PUBLIC_URL` 自动生成，真实支付启用要求公网 HTTPS。回调必须验签并核对订单、商户、方式、金额和币种；浏览器回跳不会触发充值入账。订单保留创建时的加密配置，渠道换密钥不影响旧单核对。未配置真实商户资料时，不会提供可用充值入口。

## 已确认的默认边界

| 环节 | 默认值 | 超限或失败处理 |
| --- | --- | --- |
| 每账号生成提交 | 10 次/分钟 | 429，不创建任务、不冻结余额 |
| 每 IP 生成提交 | 60 次/分钟 | 429，不创建任务、不冻结余额 |
| 每账号待审核/排队/执行任务 | 20 个，四类共享 | 429，等待完成或主动取消 |
| 充值订单有效期 | 30 分钟 | 服务端查单确认后关闭；不确定结果继续保留 |
| 渠道执行超时 | 新建渠道默认 300 秒，可按渠道调整 | 在剩余预算内切换；已输出文本或受理异步任务不重提，最终失败退款 |
| 每任务尝试次数 | 3 次，包含首次 | 运营设置 `maxAttempts`，1 关闭自动切换；无候选或耗尽后退款 |
| 连续检测失败阈值 | 3 次 | 渠道检测配置 `autoDisableAfter`，0 关闭；沿用原冷却与检测间隔 |
| 自动恢复 | 1 次有效检测成功 | 恢复自动停用状态，手动停用不自动开启 |
| 邀请充值返利 | 默认关闭，比例 0% | 按实际充值到账时配置返利，永久到账，不补发已入账订单 |
| 文本模型最大输出 token | 无默认值，必须由管理员按模型填写 | 配置缺失时在冻结前拒绝提交；用户不能覆盖，达到上限按正常完成结算 |
| 文件大小 | 沿用 50 MiB | 拒绝超限上传或生成结果，不结算失败任务 |
| 无引用媒体宽限期 | 沿用 45 天 | 仅清理没有任何业务引用的文件 |
| 请求日志保留期 | 沿用 30 天 | 清理已结束的请求日志，不裁剪余额账本 |
| 渠道检测记录 | 30 天 | 仅删除过期检测结果，不影响成本账 |
| 站内通知 | 90 天 | 过期通知及其已读记录一并删除 |
| 管理审计 | 365 天 | 删除普通审计；成本核对审计和成本账不清理 |
| 分组存储配额 | 默认 0（关闭） | 超限返回 413，拒绝新上传；生成结果无法保存时任务失败并退回冻结余额 |

前三项及订单有效期可在运营设置修改，0 表示关闭对应频控/活跃任务限制。登录保护保留 IP 30 次/5 分钟、IP+账号 5 次/分钟的失败尝试边界，并在校验密码前预占名额，成功登录退回对应名额。

## 部署

1. 首次部署：

   ```sh
   cd /opt
   git clone https://github.com/CodeWolffy/infinite-canvas-public.git
   cd /opt/infinite-canvas-public
   cp .env.example .env
   # 编辑 .env，填写公网域名和所有生产密钥
   docker compose up -d --build app api
   ```

2. 后续更新：

   ```sh
   cd /opt/infinite-canvas-public
   git pull origin main
   docker compose up -d --build app api
   ```

   `app` 和 `api` 的依赖服务 PostgreSQL、Redis、MinIO 会按 Compose 配置一并启动；站点入口按 `1Panel -> Web Nginx -> Go API` 配置，Web 仅绑定宿主机 `127.0.0.1:3000`，API、Redis、PostgreSQL、MinIO 不直接开放公网端口。
3. 本机 HTTP 使用单独配置和专用 `.env.local`：`docker compose --env-file .env.local -f docker-compose.local.yml up -d --build`，默认打开 `http://localhost:3301`；如需更换宿主机端口，在 `.env.local` 中设置 `PUBLIC_WEB_PORT`。本地配置会覆盖站点地址与 Secure Cookie。
4. 首次登录初始化管理员后修改初始密码，创建上游渠道并绑定发布模型，然后设置价格、签到、邀请码与支付渠道。

Compose 项目名为 `infinite-canvas-public`，使用独立数据卷。首次运行使用空库；Go 数据库按内置迁移顺序升级，当前到 `014_channel_capability.sql`，新增必填渠道类型。已有渠道按模型绑定填充类型，混用多种类型时拆成独立渠道并保留密钥、路由、成本与检测配置；各渠道继承原调度参数。未绑定渠道按 Claude 协议或视频适配器分类，其余先归图片，可在绑定模型前通过后台编辑更正。发现公司版 `users` 表或未知版本时拒绝覆盖，不提供公司版数据迁移。升级前备份数据库、MinIO 数据、Redis AOF 和 `CHANNEL_ENCRYPTION_KEY`；渠道、订单、邮件与 TOTP 密文均依赖此密钥。主动检测配置按绑定 ID 保存。

如果升级曾报 `column "capability" of relation "channels" contains null values`，拉取修复后的代码并按上述更新命令重新构建启动。失败的迁移已由事务回滚，修复版会从原数据库版本继续升级。

音频按秒计价需要 `ffprobe`。Go Dockerfile 已声明安装 ffmpeg；本地直接启动 Go 时，应先把 ffprobe 加入 PATH。时长读取限定本地文件协议和支持的音频容器，不允许媒体内容引导探测器访问网络。

前端保留现有 Ant Design 6 与 Pro Components beta 组合；由于其 peer 声明仍要求 antd 5，npm 安装使用 `npm install --legacy-peer-deps`，Docker 使用对应的 `npm ci --legacy-peer-deps`。也可使用项目原有的 `bun install`。本地 Vite 支持 `VITE_API_TARGET` 指定独立 Go 开发服务地址。
