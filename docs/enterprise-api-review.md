## 需求覆盖（Spec）

依据企业平台实施基线、待测试清单和用户确认的公网 HTTPS / 可选本地 Codex 边界复核。

- 文本后续请求补回历史图片，按原附件顺序发送，并将系统提示词保留为 system 角色。对应原规划的文本对话与附件持久化要求。
- 首次文本生成、多文本槽位和重试分别保存请求与对话 ID，提交后响应断线继续按服务端状态恢复，并保留已成功的其他槽位；汇总时采用当前节点状态，迟到结果不覆盖已恢复结果。提交前失败仍按失败处理。对应待测试中的多文本独立恢复要求。
- 图片前台等待结束后保留服务端任务关联，后台继续按真实状态恢复，不因浏览器等待结束而伪造任务失败。原有前台等待时间保持不变。
- 创建或恢复历史版本前等待现有保存队列完成，保存失败时停止版本操作；历史裁剪和删除项目同步释放图片引用。
- 本地 Agent 继续通过浏览器操作当前账号的画布与企业 API；登录跳转、连接参数、素材保存结果和工作台模型参数需要按待测试清单验收，不将本地 Codex 模型与平台文本模型混为一体。

## 故障转移复核

现有优先级、权重与错误切换策略符合企业实施基线。本次补齐了并发和异常路径，未改变超时、冷却、并发或切换次数的边界值。

| 情况 | 当前处理 |
| --- | --- |
| 正常路由 | 优先高优先级渠道，同优先级按权重分流；禁用、解绑或冷却中的渠道不调用 |
| 网络、超时、429、5xx、401/403 鉴权错误 | 按既有规则转向后续可用渠道；普通故障采用配置冷却，鉴权错误至少冷却 5 分钟 |
| 用户参数错误、明确内容审核拒绝 | 停止切换；识别 HTTP 200 的 OpenAI 拒绝字段和 Gemini 阻止原因，审核拒绝不误触发鉴权冷却 |
| 损坏 JSON 或无法识别的响应 | 保留最多额外切换一次；空或损坏文本响应不再因 TypeError 跳过这次机会 |
| 排队与并发冷却 | 取得槽位后重新核验可用状态；先记录故障再释放槽位，迟到成功不清除较新的故障 |
| 状态记录与结果保存 | 健康记录失败不改写上游结果；尝试记录写入失败在任务结束时补记，不能因此再次生成；MinIO 或结果事务失败不记成功费用 |

新增 30 项专项回归已通过（调度 17、图片任务状态与计费 7、上游分类 6）。OpenAI 的 `content_filter` 与拒绝字段按[官方 Chat Completions 返回结构](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/retrieve)核对。

Standards 轴确认并修复了冷却/排队状态与健康记账的问题；Spec 轴确认并修复了审核拒绝、损坏响应和尝试记账改变切换决策的问题。当前实现仍以单 API 实例为前提；持续数据库故障可能使健康或尝试记录无法持久化，会保留告警，本轮未引入新的恢复或重试策略。真实模型渠道未被本次测试调用。
