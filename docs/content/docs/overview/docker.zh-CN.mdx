# Docker 部署

本页适用于当前 Go 公益分支。后端入口为 `server/Dockerfile`，原 `api/` 不参与部署。生产镜像构建、静态资源路径与目标环境吞吐量仍需验收。

## 配置与启动

复制仓库根目录 `.env.example` 为生产配置 `.env`，替换全部 `change-me` 密码和加密密钥，并设置实际 HTTPS 域名的 `PUBLIC_URL`、`CORS_ORIGIN`。仅本机运行时，复制为单独的 `.env.local` 并使用下方 `--env-file .env.local`，不要把公司项目的 `.env` 或数据库配置用于本平台。

生产服务器更新使用新的目录名和三步命令：

```sh
cd /opt/infinite-canvas-public
git pull origin main
docker compose up -d --build app api
```

首次部署前，将生产配置保存为 `/opt/infinite-canvas-public/.env`，不要提交该文件。

本地 HTTP 使用单独配置，默认绑定 `127.0.0.1:3301`；公司项目的 `3300` 端口不属于本平台：

```sh
docker compose --env-file .env.local -f docker-compose.local.yml up -d --build
```

本地入口为 `http://localhost:3301`。如需更换本地宿主机端口，在 `.env.local` 中设置 `PUBLIC_WEB_PORT`；容器内仍使用 3000。首次登录初始化管理员后修改初始密码，再创建上游渠道、绑定发布模型、设置价格、签到区间和邀请码。真实支付需要在后台配置商户资料，并完成公网 HTTPS 通知联调。

## 服务与网络

- `app`：Nginx 静态前端；生产绑定宿主机 `127.0.0.1:3000`，本地 Compose 默认绑定 `127.0.0.1:3301`。
- `api`：Go 服务，容器内 3001，包含鉴权、任务执行与账务。
- `postgres`：权威业务数据库。
- `redis`：启用 AOF 的跨实例频控和渠道槽位。
- `minio`：私有媒体存储，媒体由已鉴权的 API 提供。

公网按 `1Panel -> Web Nginx -> Go API` 配置，生产保持 `TRUST_PROXY=true`、`COOKIE_SECURE=true`。不要直接公开 API、数据库、Redis 或 MinIO 端口。

Compose 项目名为 `infinite-canvas-public`，因此容器会显示为 `infinite-canvas-public-app-1`、`infinite-canvas-public-api-1` 等，数据库、Redis、MinIO 的卷和网络也与公司项目 `infinite-canvas` 分开。不要给这些服务添加固定 `container_name`，以免后续扩展 API 副本时产生冲突。

## 数据与支付

Go 服务只初始化独立空库；发现公司版旧表或未知版本时拒绝覆盖。数据库、对象数据、Redis AOF 以及 `CHANNEL_ENCRYPTION_KEY` 都需要纳入备份，并实际演练恢复。

支付支持易支付经典接口、支付宝当面付、微信 Native API v3。浏览器回跳不会入账；只有服务端验签和查单确认才能更新余额。经典易支付缺少统一远端关单协议，过期后关闭本站入口，迟到的真实付款仍按幂等规则入账。
