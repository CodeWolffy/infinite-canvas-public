# 公司内部创作平台二开规划

本文档记录将现有无限画布二次开发为公司 AI 图片创作平台的需求与实施基线。保留当前画布和交互，把账号、图片生成、文本对话、画布、素材和生成记录迁移到统一服务端，供用户通过公网 HTTPS 域名跨设备使用。

当前已确认采用 1Panel HTTPS 反代，源站端口不向公网开放；可选 Agent 继续运行在每位用户自己的电脑上，使用本地 Codex，不替代平台文本渠道。原先仅局域网的部署设想已由此边界替代。

本文档是本次改造的实施基线。当前实现已进入待测试阶段，实际可用范围以[待测试](/zh-CN/docs/progress/pending-test)和用户确认后的正式功能文档为准。

## 项目目标

- 基本保留现有画布、生图工作台、提示词和素材库体验，不重新设计核心创作界面。
- 由管理员创建账号，普通用户登录后直接选择模型使用，不再配置 Base URL 或 API Key。
- 用户的画布项目、节点、素材、图片生成记录和文本对话全部跨设备保存。
- 生成图片、参考图片和素材文件统一保存到 MinIO，不再以浏览器本地文件为权威数据。
- 管理员统一维护 OpenAI / Gemini 兼容渠道、公开模型、模型映射、主备顺序和价格。
- 同一公开模型可以绑定多个渠道，支持严格主备、同级权重分流和失败自动切换。
- 管理员可以按用户、模型、渠道和时间范围查看调用数量、图片数量、费用、耗时和成功率。
- 首版只改造图片和文本链路，视频、音频等入口暂时隐藏。

## 明确不在首版范围内

- 用户自行注册、企业微信、飞书、钉钉、LDAP 或统一身份认证。
- 实时多人协作、共享画布和画布评论。
- 回收站、用户存储配额、自动清理期限和历史数据迁移。
- 管理员查看提示词和生成原图的界面；但首版会保存完整归属数据，为以后增加该能力保留基础。
- 用户用量额度、超额停用、精确上游账单和 CSV 导出。
- 视频生成、音频生成和任意 JavaScript 渠道调用脚本。
- 上游所有模型自动发布给普通用户。

## 总体架构

推荐采用一个小型 TypeScript 单体后端，不直接把 New API 或 Sub2API 作为运行依赖。渠道优先级、权重、模型映射和失败切换参考中转站成熟设计，但只实现当前内部平台需要的部分。

```txt
公网 HTTPS 用户浏览器（经 1Panel 反代）
        |
        v
React 前端 + Fastify API
        |-- PostgreSQL：用户、画布、素材元数据、任务、渠道、统计、文本对话
        |-- pg-boss：持久化异步任务队列，全局并发上限 20
        `-- MinIO：参考图、生成图和素材文件
                  |
                  v
        OpenAI / Gemini 兼容渠道
```

推荐技术栈：

- 前端继续使用当前 Vite、React、React Router、TypeScript、Ant Design、Tailwind 和 Zustand。
- 后端使用 Fastify + TypeScript。
- 数据访问使用 Drizzle，数据库使用 PostgreSQL。
- 使用 pg-boss 基于 PostgreSQL 实现持久化任务队列，首版不额外部署 Redis。
- 使用 MinIO 保存二进制文件。
- 密码使用 Argon2id 哈希。
- 登录使用服务端会话和 HttpOnly Cookie，默认有效期 7 天。
- 使用 Docker Compose 部署，由 1Panel 管理容器、数据卷和备份。

选择独立轻量后端而不直接二开 New API / Sub2API 的原因：

- 当前业务只有约 5 名用户和 20 个以内的图片任务并发，不需要中转站的支付、充值、令牌分销、用户分组和复杂计费体系。
- 现有图片与文本请求代码使用 TypeScript，迁移到服务端时可以复用协议适配、响应解析和错误分类逻辑。
- New API 使用 AGPL-3.0；Sub2API 同样包含大量与公司内部创作平台无关的商业中转能力。
- 平台主要瓶颈来自上游图片模型，而不是 Node.js 的请求吞吐量。

## 公网部署边界

- 用户通过 1Panel 配置证书的公网 HTTPS 域名访问。
- 请求链路为 1Panel -> Web Nginx -> API，3000/3001 不对公网开放，API 只信任靠近它的两层代理。
- PostgreSQL 和 MinIO API 不向普通终端直接开放，只允许应用容器和必要的管理网络访问。
- 生产会话必须使用 Secure Cookie；本机 Codex Agent 是浏览器连接的可选本地插件，不在平台服务器开放 Agent 端口。
- 1Panel 管理端也应限制在管理员设备或可信管理网络中访问。

## 用户与权限

首版只有两种角色：

- 管理员：维护用户、公开模型、渠道、模型映射、价格和统计。
- 普通用户：使用创作功能、维护自己的画布和素材，并可以向公共素材库添加内容。

账号流程：

1. 管理员创建账号并设置临时密码。
2. 用户首次登录必须修改密码。
3. 管理员可以禁用账号或重置密码。
4. 禁用账号或重置密码后，该用户的全部现有会话立即失效。
5. 用户账号首版不允许删除，只能禁用，避免留下无主画布、图片和统计记录。

普通用户可以看到管理员发布的真实模型名称并自行选择模型，但不能看到：

- 渠道名称和渠道健康状态。
- Base URL 和 API Key。
- 渠道优先级、权重、上游模型映射和单价。
- 管理员统计和其他用户的私人数据。

普通用户继续可以设置模型、尺寸、数量、质量等个人生成偏好。

## 服务端数据范围

以下业务数据以 PostgreSQL 和 MinIO 为权威来源：

- 画布项目、节点、连接、视口、画布助手会话和相关项目状态。
- 私人素材和公共素材。
- 参考图片、上传图片、生成图片及其文件元数据。
- 图片生成批次、单图任务、渠道尝试和生成记录。
- 文本对话、消息、模型调用状态和响应内容。
- 公开模型、渠道、模型映射、价格和调度配置。
- 用户、会话和管理员统计所需的审计数据。

浏览器中的 localforage 不再保存权威业务列表和文件，只保留主题、临时界面状态和必要缓存。公司新部署不迁移旧浏览器数据。

## 画布保存

- 每个画布项目在数据库中保存一份完整 JSON 快照，不把每个节点拆成独立数据库记录。
- 快照包含当前 `CanvasProject` 所需的节点、连接、对话会话、背景、视口和显示设置。
- 首版不实现实时协作和冲突处理界面。
- 同一账号在不同设备同时编辑同一画布时采用后保存覆盖前保存；该场景被视为极少发生的已知限制。
- 图片节点只保存服务端文件引用和必要元数据，不把大体积 base64 写入画布 JSON。

## 文件与 MinIO

MinIO 保存：

- 用户上传的参考图片。
- 上游返回并由服务端下载的生成图片。
- 私人素材库和公共素材库中的图片文件。
- 画布和文本对话中需要长期引用的图片附件。

首版文件限制：

- 支持 PNG、JPEG 和 WebP。
- 单张用户上传图片最大 20MB。
- 单个上游生成结果最大 50MB。
- SVG 和 GIF 暂不进入图片生成链路。
- 上游图片必须成功下载并写入 MinIO 后，任务才算成功并产生费用。

文件删除采用引用检查：

- 删除生成记录时，如果图片仍被画布或素材引用，则只删除记录，不删除文件。
- 图片不再被任何画布、素材、生成记录或消息引用时，才真正从 MinIO 删除。
- 用户可以彻底删除符合上述条件的私人图片，不提供回收站。

## 私人素材与公共素材

- 图片默认属于创建用户的私人空间。
- 所有普通用户都可以向公共素材库添加素材。
- 创建者可以编辑、删除自己发布的公共素材。
- 管理员可以管理全部公共素材。
- 其他普通用户只能使用，不能修改或删除别人的公共素材。
- 用户把公共素材加入自己的画布或私人素材后形成独立引用。
- 删除公共素材条目不会破坏其他用户已有画布中的图片。
- 首版同步图片和文本素材，视频素材不纳入新的服务端链路。

## 公开模型与渠道

管理员维护用户可见的“公开模型”。一个公开模型可以绑定多个渠道，每个绑定关系可以配置不同的上游模型名称。

```txt
公开模型：gpt-image-2
|-- 渠道 A：上游模型 gpt-image-2，优先级 100，权重 100
|-- 渠道 A2：上游模型 image-v2，优先级 100，权重 20
|-- 渠道 B：上游模型 image-v2，优先级 50，权重 100
`-- 渠道 C：上游模型 gpt-image，优先级 10，权重 100
```

管理员可以为渠道配置：

- OpenAI 或 Gemini 协议。
- Base URL。
- 加密保存的 API Key。
- 启用或停用状态。
- 默认请求超时，初始值为 8 分钟。
- 单渠道最大并发。
- 优先级和同优先级权重。
- 对外模型到上游模型的名称映射。

管理员页面可以调用渠道的 `/models` 等兼容接口获取模型列表，但必须由管理员手动选择并发布，不自动把上游所有模型暴露给用户。

API Key 使用部署环境中的主密钥加密后写入 PostgreSQL。管理员页面只显示是否已配置和掩码信息，允许替换密钥，但不返回完整原值。API Key、鉴权头和解密后的秘密不得写入日志。

## 渠道调度

调度采用“优先级 + 同级权重”的组合：

1. 从支持当前公开模型且处于可用状态的渠道中选择最高优先级。
2. 最高优先级只有一个渠道时严格使用该渠道。
3. 同一优先级有多个渠道时按权重分流。
4. 当前优先级的候选渠道全部失败后，进入下一优先级。
5. 每次渠道尝试独立记录实际渠道、上游模型、开始时间、耗时、响应状态和错误分类。

允许自动切换渠道的错误：

- 网络连接失败。
- 请求超时。
- HTTP 429。
- HTTP 5xx。
- HTTP 401 或 403；同时把渠道标记为需要管理员检查或进入临时冷却。

不自动切换的错误：

- 用户参数错误。
- 明确的内容审核拒绝。
- 已确认属于提示词或输入图片的问题。

对于无法确认上游是否已经执行并扣费的模糊错误，最多额外切换一次，减少重复扣费和重复生成风险。

## 图片任务队列

用户选择同一模型生成 4 张图片时，服务端拆成 4 个单图子任务：

- 4 个子任务都使用用户选定的同一个公开模型。
- 每张图片可以独立选择渠道、重试、计费和入库。
- 某一张失败只切换或重试该任务，不影响其他图片。
- 每个单图任务占用一个全局并发名额。
- 全局同时执行的图片任务上限为 20，其余任务排队。
- 每个渠道还受管理员配置的单渠道并发上限约束。
- 默认超时为 8 分钟，管理员可以按渠道调整。
- 用户刷新、关闭页面或退出登录后，服务端任务继续运行。
- 用户重新登录后可以恢复查看批次、单图进度、错误和最终结果。

建议状态：

```txt
queued -> running -> succeeded
                  `-> failed
                  `-> canceled
```

生成批次记录用户一次操作，单图任务记录每张目标图片，渠道尝试记录每次实际请求。历史快照中的模型名称、单价和渠道归属不得因管理员后续修改配置而改变。

## 文本链路

画布助手、提示词反推等文本模型请求也统一经过后端，由管理员配置文本模型和渠道，普通用户不再提供 API Key。

首版持久化：

- 对话和消息归属。
- 完整请求消息和模型响应内容。
- 用户选择的公开模型。
- 实际渠道和上游模型。
- 状态、耗时和错误信息。
- 创建和完成时间。

文本请求暂不计算费用，不计入图片费用和图片成功率，但保留独立调用记录。文本回复需要跨设备恢复。

## 计费与统计

图片模型价格由管理员按公开模型配置，统一使用人民币“元/张”，显示和统计保留两位小数。

计费规则：

- 只有图片成功写入 MinIO 才计费。
- 按实际成功图片张数计费，不按用户点击次数或批次数计费。
- 单价暂不区分尺寸、质量和比例。
- 每张成功图片保存生成当时的单价快照。
- 失败任务和失败渠道尝试保留记录，但费用为 0。
- 首版费用是内部估算值，不承诺与中转站实际账单完全一致。

管理员统计支持：

- 今天、近 7 天、近 30 天和自定义日期范围。
- 按用户、公开模型和实际渠道筛选。
- 调用数量。
- 成功图片数量。
- 估算费用。
- 平均和分位耗时等基础耗时指标。
- 用户任务成功率：成功图片数 / 请求图片数。
- 渠道尝试成功率：渠道成功尝试数 / 渠道总尝试数。

首版不导出 CSV。提示词、请求参数和生成图片归属从第一版开始保存，但管理员查看提示词和原图的界面后续再实现。

## 推荐数据表

具体字段在实现阶段按现有代码进一步收敛，首版建议包含：

- `users`：用户名、密码哈希、显示名、角色、状态、首次改密标记。
- `sessions`：用户会话、过期时间和失效状态。
- `user_preferences`：用户个人模型和生成参数偏好。
- `models`：公开模型、能力类型、单价和发布状态。
- `channels`：协议、Base URL、加密密钥、超时、并发和健康状态。
- `model_channels`：公开模型与渠道绑定、上游模型映射、优先级和权重。
- `canvas_projects`：用户、标题、完整 JSON 快照和更新时间。
- `assets`：所有者、私人或公共范围、类型、元数据和文件引用。
- `media_objects`：MinIO 对象键、MIME、尺寸、字节数和引用状态。
- `generation_batches`：用户一次图片生成操作和请求图片数量。
- `generation_tasks`：单张图片任务、状态、模型、参数和价格快照。
- `generation_attempts`：渠道尝试、上游模型、状态、耗时和错误分类。
- `generated_images`：成功任务对应的 MinIO 文件和计费结果。
- `conversations`：文本对话及其用户、画布归属。
- `messages`：对话消息、角色、正文和附件。
- `text_requests`：文本请求的模型、渠道、状态和耗时。

## 管理后台

新增独立 `/admin` 管理入口，普通用户不可访问。首版包含：

- 创建用户、设置临时密码、禁用用户和重置密码。
- 创建、编辑、发布和停用公开模型。
- 配置模型的元/张单价。
- 创建、编辑、测试、启用和停用渠道。
- 从兼容接口获取模型列表。
- 配置上游模型名称映射、优先级、权重、超时和渠道并发。
- 查看渠道最近成功、失败、耗时和错误摘要。
- 查看并筛选用户、模型和渠道使用统计。
- 管理全部公共素材。

普通用户现有渠道配置入口需要移除或隐藏；管理员渠道维护放到独立后台，不和普通用户的个人生成偏好混在一起。

## 前端改造原则

- 保留现有 Lovart 风格画布和主要创作交互，避免不必要的界面重做。
- 登录后先加载用户、公开模型和服务端业务数据。
- 图片与文本请求统一调用项目后端，不再由浏览器直连中转站。
- 画布、素材和生成记录的 Zustand store 可以继续作为当前页面状态，但持久化动作改为服务端 API。
- 异步图片任务需要展示排队、执行、部分成功、失败和重试状态。
- 视频、音频、WebDAV、渠道配置和自定义模型脚本在普通用户界面暂时隐藏。
- 页面文案继续保持中文，并遵循当前主题和画布 UI 规范。

## 备份与运维

- 使用 1Panel 配置 PostgreSQL 和 MinIO 的每日自动备份，默认保留最近 7 份。
- PostgreSQL 与 MinIO 必须作为同一个恢复点一起备份，避免数据库记录存在但图片对象丢失。
- MinIO、PostgreSQL 和应用密钥使用独立持久化卷或明确的数据目录。
- 部署环境中的密钥加密主密钥必须单独备份；丢失后无法恢复数据库中的渠道 API Key。
- 应用日志不得输出用户密码、会话 Cookie、API Key、完整鉴权头或 MinIO 密钥。
- 首版不要求复杂监控平台，但应保留任务失败、渠道错误和队列积压的管理员可见信息。

## 实施顺序

### 第一阶段：后端基础

1. 新增 Fastify 服务、PostgreSQL、Drizzle 和基础配置。
2. 实现用户、会话、首次改密、管理员创建账号和禁用账号。
3. 增加前端登录页、路由保护和 `/admin` 权限边界。

### 第二阶段：文件与业务数据

1. 接入 MinIO 和受权限保护的上传、读取、删除接口。
2. 把画布项目改为服务端 JSON 快照。
3. 把私人素材、公共素材和图片文件改为服务端存储。
4. 移除浏览器本地业务数据的权威地位。

### 第三阶段：图片生成

1. 把现有 OpenAI / Gemini 图片适配迁移到后端。
2. 接入 pg-boss 单图任务队列和全局 20 并发限制。
3. 实现公开模型、渠道、模型映射、优先级、权重和单渠道并发。
4. 实现错误分类、渠道切换、MinIO 入库和异步进度恢复。
5. 实现按成功图片计费和历史价格快照。

### 第四阶段：文本链路

## MVP 验收标准

- 管理员可以创建、禁用和重置用户账号，首次登录必须改密。
- 普通用户登录后无需配置 API Key，可以选择管理员发布的图片和文本模型。
- 用户在不同设备通过 HTTPS 域名登录后，可以看到同一份画布、素材、生成记录和文本对话。
- 用户一次生成多张图片时，每张图片独立排队、执行、切换渠道、保存和计费。
- 页面关闭后任务继续执行，重新登录后能查看结果。
- 生成图片、参考图和素材全部由 MinIO 长期保存。
- 同一模型可以配置严格主备和同级权重分流，并能在指定错误下自动切换。
- 管理员可以按时间、用户、模型和渠道查看调用数量、图片数量、费用、耗时和两种成功率。
- 普通用户不能读取渠道地址、API Key、优先级、价格或其他用户私人数据。
- 公共素材可由所有用户添加，创建者和管理员按既定权限维护，删除不会破坏已有画布引用。
- 系统只通过 1Panel 的 HTTPS 入口提供公网访问，源站端口、数据库和 MinIO 不直接向公网开放。
